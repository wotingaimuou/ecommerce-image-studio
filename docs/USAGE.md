# 使用指南

## 最省事的用法

上传真实商品照片，调用 `$ecommerce-image-studio`，用日常语言描述平台和用途。尽量提供真实款式、尺寸、材质、价格、包装内容；没有这些信息也能先做不依赖它们的外观图。

例如：

> 这是一款咖啡杯，参考图是实际商品。给我做一张干净主图、一张桌面场景、一张容量与尺寸说明。容量和尺寸按附表，不加保温时长等没提供的功能。

Skill 会整理信息并开始工作，不要求你填写工程字段。

## 一次完整制作

1. **读图与锁定商品。** 区分不同商品、多视角、多色、模板和风格参考。
2. **整理事实。** 每条参数保留来源；未知卖点不编造。
3. **安排图片。** 每页只承担一个主要购买决策任务，指定构图、文字、人物和画幅。
4. **实际出图。** 每张资产独立调用宿主内置图像工具。
5. **逐张验收。** 对照外观、件数、文字、人物、场景和图像属性。
6. **交付。** 保存独立图片、brief、提示词及 QA；未通过项明确标注。

## 如何描述参考图

- 商品图：决定商品是什么，保持轮廓、结构、颜色、标签。
- 母版图：决定背景、排版、机位和文字层级。
- 风格图：借鉴光线、气氛和视觉语言，不借用其中的商品参数。

多色 SKU 至少需要确定母版和各颜色的商品参考；“看起来像银色”不能作为“925 银”的事实来源。

## 场景选择

| 模式 | 适合需求 | 关键约束 |
| --- | --- | --- |
| hero | 干净主图 | 工作室默认白底、无人物、无新增海报文字 |
| carousel | 轮播与卖点 | 每张有独立职责，文案有证据 |
| detail | 详情说明 | 手机端信息清晰，不编造参数 |
| retouch | 抠图与精修 | 保持外观，透明输出需真实 alpha |
| sku-color | 多色同版 | 母版锁布局，各色实物锁商品 |
| sku-bundle | 数量套装 | 件数可数且与文案一致 |
| scene | 商业场景 | 每张一个核心空间 |
| lifestyle | 自然随拍 | 自然光、真实尺度、无海报文案 |
| ad | 广告与活动 | 真实活动信息，不编造折扣 |

这些是工作室预设，不是平台官方规则；例如要做带文案的主视觉，可以用 carousel 或 ad。

## CLI：只编译，不生图

安装依赖后，从仓库根目录执行：

```bash
python scripts/studio.py plan --brief examples/concept-mug.json --out .local-run/mug
```

输出目录必须不存在，以避免覆盖。查看输出 `manifest.json` 中每张图片的 `tool_args`，由宿主调用图像工具。比例是提示词目标，实际尺寸需要验收。

### 记录生成图片

将真实输出保存为 `/path/to/generated.png`，人工或宿主目视检查后填写 QA，再执行：

```bash
python scripts/studio.py record --manifest .local-run/mug/manifest.json --asset mug-hero --image /path/to/generated.png --qa examples/qa-review.json --out .local-run/review
```

示例 QA 默认 `unverified`，所以第一次执行会返回 `needs_review` 和退出码 3。这是有意设计，只有完成实际目视检查后才把对应项改为 `pass`。

| 退出码 | 含义 |
| --- | --- |
| 0 | 命令成功；record 时表示按已提交 QA 和机器检查验收通过 |
| 2 | 输入或文件操作错误 |
| 3 | 图片已记录，但比例、透明度或视觉 QA 需要复核 |

`record` 会生成 PNG 与 receipt，包含尺寸、字节数、SHA-256、机器检查和提交的视觉 QA。它不会自动读懂图片文字或判断商品结构。

### 复现 MORA 案例

1. 运行 `plan --brief showcase/mora/brief-master.json --out .local-run/mora-master`。
2. 用宿主图像工具执行母图任务；仓库附带已生成的 `showcase/mora/images/product-master.png` 可直接用于下一步。
3. 运行 `plan --brief showcase/mora/brief-series.json --out .local-run/mora-series`。
4. 宿主按三张资产逐一调用图像工具，再进行视觉质检与 record。
5. 新图片保存到新目录，避免覆盖本次展示结果。

所有参考路径相对于 brief 文件所在目录解析。最终图可能与示例不同；生成流程可复现，像素不保证一致。

## 常见问题

**只有 Python，能出图吗？** 不能。脚本只做编排与验收，需要具备图像生成能力的宿主执行实际生成。

**需要提供 API key 吗？** 默认内置工具工作流不需要给本项目配置 API key。宿主是否能调用图像工具取决于自己的环境与权限。

**支持所有平台吗？** 可以为不同平台设计素材，但当前没有实时规则同步功能，也不保证平台审核通过。

**能保证完全保真吗？** 不能。细小刻字、复杂 Logo、珠宝链节、数量和结构必须检查；需要像素级保真时，应使用真实抠图和确定性排版。

**暂时失败会一直重试吗？** 不会。明确服务不可用/限流最多按配置重试；网络超时等结果不明时先检查已有结果，避免盲目重复生成。
