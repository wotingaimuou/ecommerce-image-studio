# 实现原理与边界

## 两层职责

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Codex 宿主 + SKILL.md | 理解需求、读图、核对事实、创意策划、调用图像工具、目视 QA | 不应把推测写成商品事实 |
| Python 辅助器 | 验证 JSON、解析本地参考图、编译提示词、检查图像文件、记录 QA | 不理解自然语言、不直接调用图像模型、不自动判断错字或商品结构 |

输入是一份结构化 brief；`src/planner.py` 校验资产职责、场景、比例、人物模式、引用角色和事实引用，再编译真实工具参数。该步骤产物状态始终是 `planned`。

`src/tools.py` 使用 Pillow 验证图片能否解码、像素数量、透明通道、目标比例和可见内容；`record_image` 合并这些机器检查与外部提交的视觉 QA，输出 `accepted` 或 `needs_review`。

**accepted 是本流程的验收状态，不等同于第三方平台审核或材质鉴定。**

## 约束

- 非概念任务必须提供 product 参考图。
- SKU 换色需要 template 与对应颜色 product。
- 套装数量必须是 1—100 的整数，显式数量文案不能冲突。
- 无文案 hero 与 lifestyle 是保守预设；带字需求改用合适模式。
- 透明要求与固定背景场景冲突时直接拒绝。
- 输入、图片大小和资产数量受 config.json 限制。
- 文件写入使用不覆盖方式，已有输出要求选择新目录。
- 未验证外观、人物或必要文案不会被判定 accepted。
- 默认工具参数来自当前宿主 schema，不能把比例等提示词属性伪装成接口参数。

## 文件与数据

辅助 CLI 不保存账号凭据，也不向外发送图片。调用宿主图像工具时，参考图的传输遵循宿主工具的数据处理机制。

reference 路径在本地编译后会成为绝对路径；分享 manifest 或 receipt 前应移除本机路径。本仓库公开的是相对路径 brief 和纯文本提示词，执行期输出放在被忽略的 .local-run 目录。

参考资料的摘要保存在 references/source-manifest.json；原始外部文本未随仓库发布，原机器路径已移除。
