# 场景路由和原指南归纳

支持多种任务模式；“多场景 Skill”不表示每张图都拼多个场景。

| 模式 | 触发需求 | 必要输入 | 画面策略与质检重点 |
|---|---|---|---|
| retouch | 白底精修、去杂背景、透明抠图 | 商品图 | 保留结构、文字、颜色；仅改授权区域；检查边缘及 alpha |
| hero | 商品首图、上架主图 | 商品；保真时需实物图 | 首先看清商品，白底/净底为保守预设，默认无新增文字与人物；这是工作室预设，不是全平台规则 |
| carousel | 轮播/卖点/细节图 | 商品、独立页面职责 | 一图解释一项决策信息；已确认事实支撑文案 |
| detail | 详情页、A+、信息海报 | 页面职责、可用事实 | 信息分层、短文案、移动端可读；按内容决定页数，不能为凑页数虚构参数 |
| sku-color | 同款多颜色选款 | 母版 + 本色实物图 + 颜色名 | 固定背景/机位/模块，替换真实产品及对应色名；不能混入不同结构；总览需实物缩略图和色名 |
| sku-bundle | 3/5/8 件套等 | 母版 + 明确件数 | 固定版式，同尺寸同款，每件独立可数；数量文案同步，不新增赠品 |
| scene | 商业产品场景 | 商品 + 场景 | 统一布景光线，场景服务用途；同组默认单一空间，用户要求多场景则逐图明确分配 |
| lifestyle | 手机随拍、生活化卖家素材 | 商品 + 日常空间 | 自然光、合理接触阴影、轻微生活痕迹；不加海报文案；“手机质感”不代表添加手机道具 |
| ad | 广告图、活动海报 | 商品 + 真实活动信息（如需） | 商品识别和单一传播重点；不得编造价格、折扣、认证和承诺 |

## 品类决策

- 服饰鞋包：穿戴关系、走线、五金、版型；尺码必须有依据。
- 美妆食品：包装、真实质地/食用状态；没有依据不画成分、营养、功效或前后疗效。
- 家居：空间比例、连接和收纳关系；没有数据不标承重/尺寸。
- 3C 家电：可见接口与操作；不能补造屏幕 UI、灯效和功能。
- 工业/B2B：规格和可见结构，未确认型号不猜。
- 母婴/宠物：实际使用关系，不因柔和外观就推断安全认证。

人物选项：`none` 连手脚也不出现；`faceless` 脸完全出画，不以口罩/墨镜代替；`allowed` 按用户明确选择和实际用途安排。自动选择时，人物对理解无帮助则不添加。

## 原指南冲突处理

来源为用户提供的 `1.txt` 至 `8.txt`，完整文件哈希见 `source-manifest.json`。

| 来源 | 实际提取 | 不机械继承的案例规则 |
|---|---|---|
| 1.txt 通用 SOP | 产品锁定、真实事实、统一套图、逐张返修 | 固定第三方工具、无条件占位文字入图 |
| 2.txt 详情页 | 产品专属页面职责、分层排版 | 每页强制 3–5 模块、只输出提示词 |
| 3.txt 全平台主图 | 首图与轮播区别、人物开关、动态数量 | 不将泛化平台建议视为最新审核规则 |
| 4.txt 多色 SKU | 母版后换产品、参考角色分离、多色总览 | 固定 8 页、强制 6 模块、无条件不反问 |
| 5.txt 数量套装 | 件数可数、数量文案同步、保留布局 | 示例 3/5/8 不成为默认订单 |
| 6.txt 品类详情 | 品类决策、无脸人物、局部细节 | 不覆盖用户明确的人物选择 |
| 7.txt 手机随拍 | 日常摄影语言、同组一致、不误添手机 | 6/8 张冲突由实际请求决定；不伪称真实消费者照片 |
| 8.txt 场景批量 | 场景基准、同组一致、逐图单场景 | 未填场景时不强制一轮单选；合理假设即可开始 |

缺失表格标有“暂时无法在飞书文档外展示此内容”，本项目未恢复或虚构这些内容。用户要求只出一张或采用特定风格时，优先执行当前要求。
